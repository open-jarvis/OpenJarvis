# فريق ميديا سوفت باك

خمسة وكلاء في فريق «سوفت باك» يعملون كنقطة واحدة: تكلّم الفريق، فيوزّع المنسّق العمل، ويعرض عليك المسودة، ولا يُجدول شيء في Buffer إلا بعد موافقتك.

| الوكيل | القالب | الأدوات |
|---|---|---|
| منسّق الفريق | `softpack_orchestrator` | `team_assign_tasks`، `campaign_files` |
| التخطيط والكتابة | `softpack_planning` | `think` |
| الصور والتصميم | `softpack_production` | `marketing_creative` + أدوات Bria من اتصالات الفريق |
| مراجعة الجودة | `softpack_quality` | `think` |
| الموافقة والنشر | `softpack_release` | `marketing_submit_review` |

## الإعداد مرة واحدة

1. افتح الفريق ← **إعدادات الفريق والاتصالات** ← اختر «منسّق الفريق».
2. في «اتصالات الفريق» اضغط **+ إضافة اتصال** واختر الخدمة. كل اتصال يُحفظ ويُختبر فورًا:
   - **Bria**: الصق مفتاح Bria API من Bria Console فقط؛ العنوان (`https://mcp.prod.bria-api.com/mcp`) وترويسة `api_token` مضبوطان تلقائيًا، ويُعلَّم كخدمة مدفوعة. بعد الاختبار تظهر أدواته، واختر «وكلاء محددون فقط» ← الصور والتصميم.
   - **Buffer**: مفتاح API من حساب الشركة (Settings ← API، بصلاحية إنشاء المنشورات)، ثم «اختبار وتحميل القنوات» واختر صفحة Facebook.
   - **Cloudflare R2**: bucket عام خاص بالشركة (معرّف الحساب، الاسم، مفتاح الوصول، الرابط العام). Buffer لا يقبل رفع الصور ويجلبها من رابط عام وقت النشر؛ تُرفع الصورة المعتمدة فقط باسم عشوائي.
   - **خادم MCP آخر**: أي MCP عبر HTTP بحساب الشركة (Bearer أو ترويسة مخصصة).

حفظ الإعداد ليس دليلًا على نجاح المصادقة: الحالة «Verified» تظهر فقط بعد طلب ناجح فعلي.

## تشغيل طلب

اضغط **كلّم الفريق** ← اكتب الطلب، وارفع صور المنتجات الأصلية والشعار، وأدخل بيانات التواصل المعتمدة كما ستظهر على التصميم، وحدد إن كانت الخدمات المدفوعة (مثل Bria) مسموحة لهذا الطلب.

1. يستلم المنسّق الطلب تلقائيًا ويوزّع المهام. كل مهمة تشغّل الوكيل المستلِم تلقائيًا، وترجع نتيجته للمنسّق.
2. الصور والتصميم: يستخدم أدوات Bria من اتصال الفريق فقط إذا سمح الطلب بالخدمات المدفوعة. يمرّر الوكيل الصورة كمسار `campaign:originals/...` فيرسل الخادم الملف نفسه دون أن يمر عبر الموديل، والصور التي تُرجعها الخدمة تُحفظ تلقائيًا في `drafts/` ويبقى الأصل كما هو. ثم `marketing_creative` يركّب العنوان والشعار وبيانات التواصل بتخطيط ثابت (لا يولّد نصوصًا بالذكاء الاصطناعي) ويصدّر PNG بمقاس 1080×1080 عبر Chrome. إذا لم يتسع النص يفشل التصدير برسالة واضحة بدل قصّه.
3. المراجعة، ثم وكيل الموافقة والنشر يرسل المسودة لك.
4. في صفحة الطلب ترى الصورة النهائية والنص والقناة والموعد بتوقيت القاهرة، ونتيجة المراجعة، وتنبيهًا إن كانت Bria قد أعادت بناء أجزاء مخفية. اضغط **أوافق — جدولة في Buffer** أو **رفض**.

الموافقة مربوطة ببصمة الصورة (SHA-256) والنص والموعد؛ أي تغيير يحتاج موافقة جديدة. بعد الموافقة يرفع الخادم الصورة المعتمدة إلى R2 وينشئ منشورًا مجدولًا واحدًا في Buffer، ويحفظ معرّف المنشور والموعد والحالة. إذا انقطع الاتصال أثناء الطلب يتحقق من Buffer قبل أي إعادة، فلا يتكرر المنشور.

## الحدود

- أي جزء أعادت Bria بناءه يحتاج مقارنتك بالأصل؛ لا يُعتبر مطابقًا تلقائيًا.
- وكيل المراجعة يعمل بالنص؛ إذا تعذّرت المعاينة البصرية يذكر ذلك صراحة، والحكم البصري لك عند الموافقة.
- الوكيل الموقوف لا يُستأنف تلقائيًا؛ مهامه تنتظر حتى تستأنفه.
- مراجع Buffer التي تم فحصها (5 نوفمبر 2026): developers.buffer.com (authentication، posts-and-scheduling، hosting-media، error-handling، api-limits). واجهة REST القديمة تتوقف في 1 فبراير 2027؛ هذا التكامل يستخدم GraphQL الحالي.
